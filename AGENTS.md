## Updating from Swiftfin

- Alphane's maintained product is the Apple TV app. Preserve Alphane's interface, interaction and tvOS-only release scope when syncing the parent repository.
- Fetch the official `jellyfin/Swiftfin` repository through the `upstream` remote. Review every incoming commit and the combined diff from the last merged upstream revision before merging.
- By default, accept compatible technical maintenance: codecs/player engines, streaming/transcoding, audio/subtitles, Jellyfin API/server compatibility, networking, persistence, security, dependencies and underlying correctness fixes. Classify mixed commits by hunk; a technical fix in a view does not authorize its accompanying redesign.
- Keep Alphane's UI, features, focus/navigation rules, setup, discovery, branding, Top Shelf and workflows. Omit upstream interface changes, iOS-only work, unrelated features and cosmetic/translation churn unless needed by an accepted technical change. Do not revive iOS builds or release automation.
- The iOS app and its unused code have been removed. During every Swiftfin merge, reject newly added or resurrected iOS-only targets, source/resources, dependencies, routes, functions and settings, including iOS branches inside otherwise shared files. Keep the tvOS implementation of mixed-platform changes. Check the final project, package manifests and active source for accidental reintroduction before finishing the real merge; preserve required Apple capability identifiers, host macOS tooling, server-client recognition and third-party/generated compatibility declarations.
- For a potentially useful new feature or major behavior/architecture change, explain its benefit and impact and ask the user before accepting it. Continue independent work while awaiting an answer. Without approval, retain Alphane's behavior and record the deferred feature; do not treat silence as approval.
- Incorporate the reviewed upstream tip with `git merge --no-ff --no-commit upstream/main`, resolve conflicts, then create a real two-parent merge commit. Preserve upstream history even for rejected changes. Do not use a squash, cherry-picks, selective backports, handwritten replacements for the merge, or the `ours` merge strategy as a shortcut.
- During the merge, retain compatible upstream technical hunks and explicitly restore Alphane's versions of unwanted hunks/files. Preserve project paths/module names and Swiftfin's licensing/attribution. Never overwrite unrelated local work; checkpoint authorized pending changes before merging.
- Record the exact upstream SHA, accepted technical changes, rejected/deferred changes and reasons, conflict resolutions and validation in the merge commit message. A complete upstream ancestry does not mean all upstream behavior was adopted.
- Build the complete tvOS product (app and Top Shelf extension) and run Apple TV regression tests before finishing the merge. Review Home discovery, playback completion/continuation, focus restoration, navigation, branding and Top Shelf. If setup/focus is affected, manually walk through it as well; do not create a UI test merely to substitute for a requested manual check.
- Verify there are no unresolved conflicts, the commit has two parents, `git merge-base --is-ancestor <reviewed-upstream-sha> HEAD` succeeds and `git rev-list --count HEAD..<reviewed-upstream-sha>` returns zero. Fetch again before reporting current status; review any newly arrived commits separately.
- Never force-push or rewrite published history. Push or deploy only when requested. A completed local merge can be up-to-date with upstream while the remote fork remains behind until pushed.
